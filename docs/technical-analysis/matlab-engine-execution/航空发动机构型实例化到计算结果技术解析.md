## 2. 三类图和四种载荷

### 2.1 三类图

| 图 | 存储位置 | 节点与边 | 决定什么 |
|---|---|---|---|
| 递归工程图 | `scenes` | 子系统、编译期装配节点、MATLAB 节点；普通数据边 | 编辑层级、边界映射与数据依赖 |
| 物理关系图 | `physicalAssemblies` | 部件成员、flow 关系、shaft/bleed 组 | 装配描述与 MATLAB 的 F/SHAFT/EXT |
| 扁平执行 DAG | 后端可信编译产物 | 可执行 MATLAB/Bus 节点与数据边 | Julia 实际调用顺序 |

气路有方向；轴系和引气表示组成员关系。它们不作为 Julia 的计算边。画布端口、物理端口、MATLAB 函数参数不是同一层概念。

### 2.2 四种载荷及版本

| 载荷 | 当前版本 | 生成者 | 使用者 |
|---|---|---|---|
| 工程文档 `projectData` | 数字 `3` | 前端编解码 | 保存加载、编辑器 |
| 候选执行载荷 | 数字 `2` | `compileExecutionPayload` | Java 层级/可信编译 |
| 可信执行图 | 字符串 `matlab.execution.v1` | Java | Python、Julia |
| 物理描述 `assembly_json` | 字符串 `engine.physical-scene.v1` | Java 装配编译 | MATLAB 初始化入口 |

结果另用 `matlab.public-result.v1`。这些版本表示不同协议，不要求数字一致。候选载荷不是 Julia 代码；`assembly_json` 也不是已经求解的 DP。

### 3.2 拖入入口与 ID 深复制

页面 `loadComponents` 同时读取目录与配置 schema，并附加前端内置 Bus、In/Out。`handleComponentDragStart` 把目录项写入拖拽数据；`handleDrop` 按 Bus、边界声明、模板、普通函数分支处理。

### 3.3 当前模板的实际层级

```text
工程根场景：一个完整构型实例
  workflow：设计点模型、工况扫描、特性图绘制；4 条数据边
    design_point：发动机组装 → 设计条件设置 → 设计点平衡求解；2 条数据边
      physical（标题“发动机组装”）：装配关系 → DP组装；1 条数据边
        assembly_relations：气路部件；普通数据边为 0
    scan：初始化 → 功率 → 速度重置 → 速度 → 高度 → 汇总；5 条数据边
    plot：三种绘图节点；相互之间数据边为 0，输入通过边界映射进入
```

`physical` 只是沿用的 Scene ID，不表示特殊 Scene 类型。工况设置透传节点已经移除，V/M/H 通过子系统边界直接进入 DP 组装。

完整构型第二层的 4 条数据边是：设计点 DP→扫描 DP、设计点 DP→绘图 DP、扫描 MISSION_power→绘图 MISSION_power、扫描 MISSION_final→绘图 MISSION_final。其余公开结果直接映射，不需要再造连线。

### 4.1 唯一编辑状态

是权威绑定来源。`resolveAssemblyInitializer/synchronizeAssemblyBindings` 通过普通边界映射追踪连接，更新 `initializerBinding` 摘要。Java 再独立追踪和校验，不仅相信该摘要。

### 4.3 通用子系统与显式 In/Out

[sceneCommands.ts · export const inferSubsystemBoundaryPorts](<C:/Users/xiong/Documents/Model-Cloud-ExtendML/model-cloud-frontend/src/features/matlab-modeling/domain/sceneCommands.ts:102>) 处理自动端口推导与封装重接；`boundaryComponents.ts` 处理显式 In/Out 和接口同步。输入支持 `mappings` 一对多，输出映射一个来源。物理端口不生成通用数据接口。

封装的计算含义在后端展开时实现，前端只是编辑和保存层级；Julia 看不到普通子系统外壳。输入值优先级：父层数据连线 → 子系统显式值 → 内部节点值 → 可信目录默认值。默认值仍保留在内部，解封装不把父层覆盖写回内部原值。

Ctrl 快捷连接由 `portAutoMatcher.ts` 语义匹配，影响建图过程，不参与运行时数值计算。In/Out 声明节点在前端生成候选载荷时消除；根层未归属声明节点会阻止提交。

### 4.4 保存、加载和提交是不同操作

`useMatlabProject` 调用项目 API 保存 `projectData`；`projectCodec.ts` 序列化节点、边、边界映射和 viewport。[MatlabModelDeploy.vue · const handleLoadProject](<C:/Users/xiong/Documents/Model-Cloud-ExtendML/model-cloud-frontend/src/views/business/MatlabModelDeploy.vue:2739>) 读取工程并重建运行时画布。

当前 `dataEdgeAdapter.ts` 按保存端点读取，不猜测缺失端口，不自动删除重复连线。异常边保留并标未解析。前一轮已删除旧发动机层级恢复、零接口补齐和重复边自动清理。V2→V3 格式导入器仍在，不能说项目完全没有兼容转换代码。

计算按钮提交的是当前内存快照，不要求先保存数据库工程；`useMatlabExecution.lastSubmission` 记录候选载荷和节点名称映射。后续结果按提交时刻关联，用户继续编辑画布不应改写既有任务结果。

### 5.3 Java 装配编译

[EngineAssemblyCompiler.java · static void applyAssemblies](<C:/Users/xiong/Documents/Model-Cloud-ExtendML/model-cloud-backend/src/main/java/com/modelcloud/modules/business/service/impl/EngineAssemblyCompiler.java:52>)：

1. 从可见数据图及嵌套边界映射找出唯一的 DP 组装输入。
2. 校验装配描述身份、子 Scene、成员、可信部件能力、气路端口。
3. 合并可信部件默认参数与实例 `assemblyDefaults`，实例值覆盖目录值。

### 5.4 可信 DAG 定型

[MatlabTrustedGraphCompiler.java · Map<String, Object> buildTrustedGraph](<C:/Users/xiong/Documents/Model-Cloud-ExtendML/model-cloud-backend/src/main/java/com/modelcloud/modules/business/service/impl/MatlabTrustedGraphCompiler.java:39>) 重新用服务端目录生成 `functionName/sourceRelativePath/inputs/outputs/invocation`，不执行前端自报的任意函数。

校验有限数字、数值向量/矩阵、字符串和布尔；DP/scan_state 等结构体由连线提供。每个目标输入只允许一个数据来源。拓扑排序使用按节点索引排序的优先队列；环路直接报错。最终输出 `matlab.execution.v1`、有序 nodes、edges、executionOrder、publicOutputs。

该阶段报错属于“提交失败”，MATLAB 还未运行。Java 中部分通用错误文案仍写 PMSM，不代表实际执行的是 PMSM 模型。

## 6. Python 任务与 Julia 运行

### 6.1 任务目录及进程边界

Java 生成字符串 taskId，并保存数据库数字 id；前端查询数字 id，Java 转为字符串 taskId 调用 Python。

[main.py · async def submit_simulation](<C:/Users/xiong/Documents/Model-Cloud-ExtendML/model-cloud-simulation/app/main.py:329>) 建立 pending 状态并异步启动 `_execute_task`，调用 [julia_matlab_graph_executor.py · def execute(self](<C:/Users/xiong/Documents/Model-Cloud-ExtendML/model-cloud-simulation/app/executors/julia_matlab_graph_executor.py:98>)。执行器再次校验协议、端口、依赖顺序、函数源码路径、资源 SHA-256。

每个任务生成：

```text
<MATLAB_TASK_WORK_DIR>/<taskId>/
  trusted_graph.json
  generated_workflow.jl
  result.json
  julia_stdout.log / julia_stderr.log
  task_status.json
  design/*.png、power/*.png、final/*.png
  plots/<phase>/*.png             # 对外服务的图片归档
```

Python 以 `subprocess.run(shell=False, cwd=task_dir)` 启动 Julia。默认任务超时为 3600 秒，并发会话默认 1；实际运行值由环境配置决定。协调器是 Python 进程内信号量，不能推断为跨多个服务进程的全局互斥。

一个任务使用一个 Julia 进程和一个默认 MATLAB Engine 会话。不是每个组件启动 MATLAB，也不是所有任务共用永久会话。任务状态通过 `task_state.py` 落盘；completed 结果恢复与重新计算是不同机制。

### 6.2 Julia 自动生成的是连线调度代码

生成代码示意：

```julia

node_conditions = execute_node!(ACTIVE_RUNTIME[], "conditions_id",
    Dict("DP" => output(node_initialize, "DP")))
```

## 9. MATLAB：工况扫描

当前模板使用六个阶段，不调用整段 `component_run_engine_envelope`。后者是可单独拖入的替代入口，共用相同阶段函数。

| 阶段 | 核心行为 | 原 TURBOSHAFT_MAIN 对应操作 |
|---|---|---|
| initialize | READMAP；OP=DP，X0=0，DX=0；首个 OFFDESIGN 丢弃 DX | 建图谱、清空数组、初始化 |
| power | linspace(1,.01,NP)；仅变 PWG(1)；N_ref=-DP.N_ref | 降功率段 |
| speed_initialize | OP=DP、X0=0；求解后不覆盖已有 DX | 速度段前重置 |
| speed | 逐次 V-=DP.V_max/NV；PWG=DP.PWG | 降速度段 |
| altitude | 不另行重置，继续逐次 H-=DP.H_max/NH | 降高度段 |
| finalize | 导出 MISSION、累计数组、最终 OP/X0/DX | 最后一份 MISSION |

`BALANCE_FUNCTION_OFFDESIGN` 以 OFFDESIGN 为残差函数，构造 NBY+NC+NT+NS+温度未知量及可选推力变量；未知转速由负 N_ref 控制。每一点重新求稳态平衡，不是发动机时间域积分。

`MISSION_power` 是功率段快照；`MISSION_final` 是三段累计后的结果；公开 `MISSION` 和 MISSION_final 映射同一 finalize 输出。额外名字来自平台公开接口，原脚本只是两次给同一 MISSION 变量赋值。最终 OP 包含最后工况状态，累计工作点没有逐点保存完整 OP，因此不能将这些输出直接当成完整飞行任务时序。
